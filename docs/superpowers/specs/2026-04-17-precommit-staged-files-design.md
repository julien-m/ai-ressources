# Design : Pre-commit hooks — staged-file awareness

**Date:** 2026-04-17
**Skill:** conventions.init / conventions.refresh

---

## Contexte et problème

Les hooks pre-commit générés par `/conventions.init` utilisent des commandes qui analysent **tout le projet** :

```sh
check "npx biome check ."
check "ruff check ."
check "npx eslint ."
```

C'est lent (scan inutile de fichiers non commités) et incohérent avec les CI templates, qui depuis le commit `8802efb` utilisent déjà `tj-actions/changed-files` pour limiter l'analyse aux fichiers modifiés.

`/conventions.refresh` ne détecte pas ce pattern périmé et ne propose pas de régénérer les hooks.

---

## Solution

### 1. Pattern staged-file dans les hooks générés

Les linters/formatters (Biome, ESLint, Ruff) passent en mode **staged-only** :

```sh
# Collect staged files by type
STAGED_TS=$(git diff --cached --name-only --diff-filter=ACM \
  | grep -E '\.(ts|tsx|js|jsx|mjs|cjs|json)$' \
  | tr '\n' ' ')

if [ -n "$STAGED_TS" ]; then
  check "npx biome check $STAGED_TS"
fi
```

Les outils qui nécessitent le projet complet restent inchangés :
- `npx tsc --noEmit` — typecheck cross-fichiers
- `cargo check`, `cargo clippy` — compilation Rust
- `go build ./...`, `go vet ./...` — build Go
- `pyright`, `mypy .` — typecheck Python

### 2. Détection de hooks périmés dans conventions.refresh

`conventions.refresh` Step 4 est étendu. Avant de régénérer les hooks pour cause de changement de stack, un check de staleness est ajouté :

**Conditions pour auto-régénération :**
1. `.githooks/pre-commit` existe ET contient `# @generated by conventions.init`
2. Le manifest du projet contient au moins un linter staged-capable (Biome, ESLint, Ruff)
3. Le hook ne contient **pas** de pattern staged-aware (`$STAGED` ou `--diff-filter`)

**Comportement :**
- Si lignes custom détectées sous la zone générée → warn avant overwrite
- Overwrite limité à la zone générée (entre le sentinel et la fin du script généré)
- Ordering : hook regeneration se fait **après** l'écriture du nouveau manifest

## Architecture des changements

### `code-conventions/stack-commands.md`

La colonne "Pre-commit Commands" est mise à jour avec le shell réel pour les linters staged-capable. Le format actuel (commandes simples) est remplacé par des snippets shell annotés.

### `claude/skills/conventions.init/SKILL.md` — Phase 7

L'exemple du hook TypeScript + Biome est mis à jour pour montrer le pattern staged-file complet, incluant :
- Collection des fichiers staged par extension
- Guard `[ -z "$STAGED" ]` avant chaque appel linter
- Maintien des commandes whole-project pour typecheck

### `claude/skills/conventions.refresh/SKILL.md` — Step 4

Nouvelle section **4b — Hook staleness check** :
- Lecture du manifest pour détecter les linters
- Grep du hook pour absence de pattern staged-aware
- Auto-régénération (sentinel = consentement implicite)
- Warn si lignes custom détectées

## Comportement attendu

### Avant (hooks générés aujourd'hui)

```sh
check "npx tsc --noEmit"
check "npx biome check ."   # ← scan tout le projet
```

### Après (hooks générés demain)

```sh
check "npx tsc --noEmit"

STAGED_TS=$(git diff --cached --name-only --diff-filter=ACM \
  | grep -E '\.(ts|tsx|js|jsx|mjs|cjs|json)$' \
  | tr '\n' ' ')
if [ -n "$STAGED_TS" ]; then
  check "npx biome check $STAGED_TS"
fi
```

### conventions.refresh sur projet avec vieux hook

```
Pre-commit hook check:
  ⚠ Hook uses whole-project linter pattern (npx biome check .)
  Regenerating with staged-file pattern...
  ✓ .githooks/pre-commit updated
```

---

## Edge cases

| Cas | Comportement |
|-----|-------------|
| Commit de `.md` uniquement | `STAGED_TS` vide → linter skippé, tsc continue |
| Commit d'un seul fichier `.ts` | Biome check sur ce fichier uniquement |
| Hook sans sentinel | conventions.refresh ne touche pas au hook |
| Lignes custom après le bloc généré | Warn + confirmation avant overwrite |
| Stack TypeScript sans Biome/ESLint | Pas de staged guard (rien à limiter) |
| Stack multi (TS + Python) | Chaque linter a son propre STAGED var |
