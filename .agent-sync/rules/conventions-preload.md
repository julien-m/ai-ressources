# Conventions

`$AIRESOURCES` designe le clone ai-ressources (variable exportee par son `setup.sh` ; lis-la avec `echo "$AIRESOURCES"`). Si elle est vide, signale-le une fois et continue sans les conventions transverses.

- Si le repo a un dossier `.conventions/`, lis `.conventions/index.md` avant de coder ou de concevoir, puis seulement les fichiers sources du sous-domaine concerne (lignes `→`, prefixe de dossier valable pour toute la ligne), en appliquant les exclusions `⊘`. Pour un sujet hors index, consulte `$AIRESOURCES/index.yaml`.
- Pour toute creation, modification ou revue d'interface (site web, application web ou native, composants inclus), lis obligatoirement depuis le clone resolu les [regles de layout et d'espacement](../../design/tokens/spacing.md) et les [regles de revue UI](../../design/quality/ui-rules.md), puis le guide de plateforme concerne dans `design/systems/`. Ce chargement s'applique meme sans `.conventions/`, avec un ancien index ou sans domaine design selectionne ; il ne depend pas d'un rappel utilisateur. Applique les layouts imbriques et les espacements pilotes par le parent dans le code livre, et transmets ces regles aux sous-agents concernes.
- Pour toute conception, planification, modification ou revue de modele de donnees (tables, relations, champs, etats, enumerations, vues ou migrations), lis obligatoirement depuis le clone resolu les [conventions de base de donnees](../../code-conventions/database.md), notamment le contrat du premier plan (§0), avant de proposer le schema ou le plan. Ce chargement s'applique aussi aux commandes LiveSpec/APEX et aux projets existants, meme sans `.conventions/`, avec un ancien index ou sans domaine code/database selectionne ; il ne depend pas d'un rappel utilisateur ni d'un rafraichissement du manifeste.
- Un sous-agent qui code ou concoit recoit le contenu des conventions applicables dans son brief ; cela inclut ceux qui planifient ou relisent un modele de donnees.
- Si `.conventions/` manque alors que le projet contient du code ou du design, ou s'il est a l'ancien format (sans `manifest.yaml`, avec des fichiers compiles comme `design.md`), propose une fois `/conventions-init` ou `/conventions-refresh --full`, sans bloquer.
- Conventions transverses : avant de creer, renommer ou supprimer un fichier, lis `$AIRESOURCES/conventions/naming.md` ; en cas de conflit entre conventions, `$AIRESOURCES/conventions/authority.md` ; pour un diagramme, un flow ou des criteres d'acceptation, `$AIRESOURCES/conventions/diagrams.md`.
