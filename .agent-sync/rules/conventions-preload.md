# Conventions

`$AIRESOURCES` designe le clone ai-ressources (variable exportee par son `setup.sh` ; lis-la avec `echo "$AIRESOURCES"`). Si elle est vide, essaie dans cet ordre `ai_resources_path` du manifeste `.conventions/manifest.yaml`, puis la declaration du chemin dans `.conventions/index.md` ; retiens seulement un dossier existant. Si un chemin est resolu, utilise-le silencieusement pour cette session, sans avertissement sur la variable. Sinon, signale une fois le chemin manquant seulement si la tache necessite ces conventions, puis continue sans les conventions transverses.

- Si le repo a un dossier `.conventions/`, lis `.conventions/index.md` avant de coder ou de concevoir, puis seulement les fichiers sources du sous-domaine concerne (lignes `→`, prefixe de dossier valable pour toute la ligne), en appliquant les exclusions `⊘`. Pour un sujet hors index, consulte `$AIRESOURCES/index.yaml`.
- Pour toute creation, modification ou revue d'interface (site web, application web ou native, composants inclus), lis obligatoirement depuis le clone resolu les [regles de layout et d'espacement](../../design/tokens/spacing.md) et les [regles de revue UI](../../design/quality/ui-rules.md), puis le guide de plateforme concerne dans `design/systems/`. Ce chargement s'applique meme sans `.conventions/`, avec un ancien index ou sans domaine design selectionne ; il ne depend pas d'un rappel utilisateur. Applique les layouts imbriques et les espacements pilotes par le parent dans le code livre, et transmets ces regles aux sous-agents concernes.
- Pour toute conception, planification, implementation ou revue de code, lis avant le premier plan les [regles generales](../../code-conventions/general.md), les [regles d'architecture](../../code-conventions/architecture.md), les [regles de tests](../../code-conventions/testing.md) et de [logs](../../code-conventions/logging.md), puis les deltas langage/framework et leurs heritages selectionnes dans [l'index code](../../code-conventions/index.yaml) selon la stack observee. Applique ce chargement aux projets existants et aux commandes LiveSpec/APEX, meme sans `.conventions/`, avec un ancien index ou sans domaine code selectionne ; aucun rappel ni rafraichissement du manifeste n'est requis.
- Lors de la revue d'un plan de code, applique le [controle de conformite code](../../code-conventions/general.md#code-planning-and-evidence-based-plan-review) : exige les preuves par module/contrat, les verifications prevues et les exceptions justifiees. Une lecture declaree ne vaut pas conformite ; un manque ou une contradiction applicable bloque l'approbation. Transmets les conventions et ce controle au reviewer, y compris pour LiveSpec/APEX.
- Pour toute conception, planification, modification ou revue de modele de donnees (tables, relations, champs, etats, enumerations, vues ou migrations), lis obligatoirement depuis le clone resolu les [conventions de base de donnees](../../code-conventions/database.md), notamment le contrat du premier plan (§0), avant de proposer le schema ou le plan. Ce chargement s'applique aussi aux commandes LiveSpec/APEX et aux projets existants, meme sans `.conventions/`, avec un ancien index ou sans domaine code/database selectionne ; il ne depend pas d'un rappel utilisateur ni d'un rafraichissement du manifeste.
- Lors de la revue d'un plan touchant aux donnees, applique le [controle de conformite du plan](../../code-conventions/database.md#01-evidence-based-plan-review-gate) (§0.1) : compare le contenu du plan aux conventions, cite les preuves par table/champ et justifie les exceptions ou non-applicabilites. Une lecture declaree ne vaut pas conformite ; un manque ou une contradiction bloque l'approbation du plan concerne. Transmets ce controle et les conventions au reviewer.
- Un sous-agent qui code ou concoit recoit le contenu des conventions applicables dans son brief ; cela inclut ceux qui planifient ou relisent du code ou un modele de donnees.
- L'absence de `.conventions/` ou de `manifest.yaml` ne declenche aucun message au demarrage ni pendant une tache ordinaire. Lors d'une demande d'initialisation, d'audit ou de rafraichissement des conventions, propose `/conventions-init` si le dossier manque, ou `/conventions-refresh --full` si le format est ancien ; ne bloque pas la tache pour cette seule absence.
- Conventions transverses : avant de creer, renommer ou supprimer un fichier, lis `$AIRESOURCES/conventions/naming.md` ; en cas de conflit entre conventions, `$AIRESOURCES/conventions/authority.md` ; pour un diagramme, un flow ou des criteres d'acceptation, `$AIRESOURCES/conventions/diagrams.md`.
